# Codex Pocket：产品与交互方案

状态：0.2.0-pocket固件与0.7.0-pocket.2电脑端已实现，已通过编译、主机检查和实际LVGL界面渲染；新固件已获用户明确批准并刷入，启动、界面、BLE和真人音频转写已通过，正在处理电脑端落字兼容。实机听写、输入框落字、提示音与续航需要刷入后验收。详见[实施与验证记录](codex-pocket-v2-validation.zh_CN.md)。本方案不代表授权新的刷机、提交、推送或发布。

## 产品定位

在 Mac 附近随身佩戴的工作伙伴：闲时是熟悉的宠物，唤醒后一眼看额度，有事时给出清晰的下一步，想输入时按住说话。精致感来自可读的层级、克制的画面和可预期的实体按键；240×320的小屏每次突出一件主要的事。

## 用户想法与解释

四个方向是个人Codex宠物屏保、大数字与剩余量圆环、专业的任务提醒、长按确认键使用工牌麦克风向电脑输入文字。“声誉额度”按前文理解为Codex剩余额度；继续采用附近Mac与BLE连接。预览中的数字和听写文字都是示意，不采集真实麦克风音频。

已通过本地选择记录和Pets插件确认当前宠物为“NOMI风格”。原图实际为1536×2288的v2精灵图，含九行动作和十六个环视方向。原图和确定性缩小的预览资源保存在[assets/pets/nomi](../assets/pets/nomi/source.json)，没有重新绘制或改变账号的宠物选择。首版可直接导入这只宠物；未来自动跟随云端换宠物，还需要稳定且已授权的资源同步接口，当前尚未建立。

## 核心体验与状态优先级

| 状态 | 画面和操作 |
| --- | --- |
| 宠物屏保 | 低干扰的待机与眨眼。任意键短按只唤醒：没有提醒时进入额度首页，有提醒时进入优先事项。 |
| 额度首页 | 大号等宽数字与单个自定义剩余量圆环；周期、重置倒计时、同步状态为次要信息。上下键查看各额度周期，默认显示最紧的有效周期。 |
| 任务提醒 | 一屏一条：类别、项目/聊天标题（最多两行）、简短下一步、队列位置。短按确认接手并在电脑定位已验证的聊天；实际审批仍在Codex中处理。 |
| 按住听写 | 长按确认进入准备/录音状态，松手结束；显示目标输入位置，并区分准备、录音、识别、已插入、保留草稿。不会自动发送提示词。 |

录音期间维持当前交互，普通新提醒排队到录音结束或取消后再处理。提醒优先级采用需要输入、异常、结果就绪、执行中。按键按下时绑定当前提醒ID，按下和松开之间的队列重排不能把操作对象换成另一件事。

空闲不等于所有项目完成；轮次结束表示回复/结果就绪，不保证部署或整个项目已经成功。未知或过期的额度明确显示待同步，不画成0%或满环。按照接口实际返回的周期和重置时间显示，不把所有账号的周期写死。

## 按键约定

- 屏保下任意键短按：只唤醒。
- 上/下：额度页切周期，提醒页切任务。
- 提醒页短按确认：接手并定位任务；其他页面执行当前主要操作。
- 所有状态长按确认，包括屏保：语音输入。现有的长按确认菜单改放到长按上键或同样明确的快捷入口。
- 唤醒防误触只抑制那次短按，不能一并吞掉后续长按或松手事件。测试屏保唤醒、长按、松手、新提醒到达、重复按键与取消。

按下立即给视觉反馈；只有录音和Mac通道准备好后才给“可以说话”的反馈。长按阈值和感知延迟以实机调校。准备超时应返回可操作状态，只在明确的听写交互期间录音。

## 听写提示音与回执：建议方案

已确认的声音形式：开始音和完成音均使用不同的、简短的非语音音效，不朗读“可以讲话”“草稿已准备好”等句子。这些文字只用于屏幕说明音效的含义。开始采用轻短单音，完成采用容易区分的上行双音，具体音色在工牌扬声器上调校，并配合文字与NOMI表情反馈。本次决定针对听写提示音，普通任务提醒语音属于另一项功能。

用户提出常态两个提示音：长按后的开始音、音频送达电脑后的确认音。保留常态两种音效，推荐进一步将普通完成音绑定到“最终文字已填入目标草稿”，音频完整到电脑作为中间视觉状态。这样声音确认的是用户想得到的结果。如果选择仅确认上传，名称必须是“电脑已接收”，继续显示识别进度，不能称为“输入成功”。

| 时机 | 声音 | 画面和必要条件 |
| --- | --- | --- |
| 识别到长按 | 暂不响开始音 | 显示“准备中”，绑定输入目标，准备采音、电脑接收和转写会话。 |
| 可以开始讲话 | 轻、短的单提示音 | 两端都准备好；提示音结束后开始有效录音，显示“正在听”和真实采集反馈。讲话时继续按住。 |
| 松开 | 不增加常态第三声 | 本地立即停止采音，关闭本段音频流，显示“正在处理”。 |
| 电脑收齐音频 | 不响完成音 | Mac确认本次音频序号/尾包完整，显示“电脑已接收，识别中”。 |
| 最终文字已填入 | 与开始音明显不同的短上行完成音 | Mac确认非空最终文字已插入正确输入位置后才触发，显示“草稿已准备好”，发送仍由用户决定。 |

音长可从开始音约80–120毫秒、完成音约150–250毫秒起调，音色、响度和声学尾音必须用工牌小喇叭实测。两种音效靠节奏/音高走向区分，不只调整音量。不能因为按住了按钮就响“准备好”，也不能用固定延时或发送函数返回来伪造完成。

另有一个轻、低的注意提示音，含义是“请看一下设备”：连接不可用、没有有效讲话、音频不完整、识别失败，或文字已保留但没有填入。搭配具体文字和NOMI表情；仅保留草稿不响普通完成音。处理较慢时保持明确状态；超时或中断指出具体阶段，仅承诺保留电脑实际收到的数据。工牌缓存有限，不能保证断线后所有讲话都能找回。

开始提示音不能进入识别结果；需要按真实播放结束和实测消尾时间控制有效录音，再测首尾字是否完整。录音时推迟普通任务播报。初版串行完成一段采集/转写；上一段还没结束时再次长按，只显示处理状态，不再发出新的可讲话提示音。

准备、收齐、转写、插入等回执均绑定本次录音ID，忽略过期或不匹配的回复。文字插入必须幂等，重连可恢复状态，不得重复插入同一段。缺少最终回执时不能显示成功。静音时仍提供完整的文字/图标反馈；主动听写提示音可单独设为轻音或关闭。

## 语音输入实现

建议链路：ES8311麦克风 → 固定大小的采集块 → 压缩BLE音频帧 → Mac解码 → Apple SpeechAnalyzer/SpeechTranscriber → 最终文字 → 目标输入框或保留草稿。

只读检查发现本机SpeechTranscriber可用，支持45种语言资源、已安装11种，其中包含zh_CN和zh_TW。检查没有录音、下载模型或改变权限。这证明资源就绪，不等于已经验证准确率或端到端延迟。优先采用系统本地转写；如需兼容或进一步比较，再评估本地whisper.cpp。初步方案无需付费云端转写服务。

AI Passport仓库有单块工牌加Android手机的Opus语音上传经验：16kHz单声道、60ms帧、约3KB/s、24KB静态编码任务栈。它是可行性参考，不是这台Mac的实测。先测MTU、持续吞吐、包间间隔和延迟，再定缓存和编码参数。音频使用独立于JSON提醒消息的通道，包含录音ID、序号、有界缓存、流控、取消及开始/结束确认。

Mac在录音前绑定目标：已确定的对应Codex任务，或用户预期的可编辑输入框。保留光标/选区和原稿；目标或原稿改变时保留独立转写稿，由用户明确插入。没有目标、权限未允许、断线或识别失败时也应保留可恢复草稿。首次使用引导辅助功能权限。本版采用SpeechAnalyzer在本机识别，不调用SFSpeechRecognizer的服务器识别授权，也不申请Mac麦克风权限。当前链路是BLE数据服务，不能仅把工牌选成普通蓝牙麦克风来完成方案。

播放与录音由同一音频管理任务串行调度；听写时暂停或推迟语音提醒。阻塞采集、采样格式切换和休眠唤醒不进入按键回调或LVGL；流控不能吞掉松手和取消。需要实测真实人声、中文准确率、首尾字截断、录音中断和跨应用焦点变化。

## 内存与功耗

首版实际启动日志约有101KB空闲堆，这是起点，不保证所有工作状态都相同。96×104的RGB565单帧需要19,968字节；整屏240×320单帧则需153,600字节，尚未计入透明度等资源。宠物帧放闪存、限定局部区域、只用小缓存，并复用现有分块刷屏路径，不为阴影或透明效果启用整屏合成。

录音编码前释放可选的宠物解码缓存，测最大连续空闲块和任务栈峰值，录音界面保持简单。额度环采用LVGL几何绘制，大数字只生成必要字形。宠物低帧率播放，进一步空闲后可停在静帧并调暗；这是TFT屏，续航主要取决于背光与各子系统功耗，提醒到来仍要及时亮起。续航和蓝牙距离以实测为准。

## 推荐扩展，按优先级

1. 接手时一键定位准确聊天；导航目标从Mac可信任务映射及支持的深链接取得。
2. 简短多任务队列，让宠物表情映射真实工作状态。
3. 低额度/重置提示、实体专注/勿扰操作，继续复用Mac现有规则，不另设一套提醒调度。
4. 个人听写术语表，以及Codex/其他输入框的明确目标选择。
5. 后续提供小型本地配件配置接口，让Codex工作流帮助调整主题和提醒规则。它需要单独定义并授权，不能因官方Micro支持某动作就认为本工牌已支持。

## 实施与验收顺序

先确定视觉与交互方向，再实现UI/宠物/额度元数据和录音/上传/转写/草稿链路。编译和测试完成后再对一份明确的新固件发起刷入确认；对0.1.0-codex的既有批准不等于批准另一份构建。

验收覆盖：四态真实屏幕可读、唤醒不误接手、屏保直接长按录音、队列重排不换错对象、未知额度、宠物状态、录音准备反馈、按下/松手/取消、本地中文识别、准确光标落字且不自动发送、焦点变化/断线保留草稿、重连、内存和连接长测、续航与距离。

## 本次实现取舍

- 编码采用独立块IMA-ADPCM：16kHz单声道，每20ms、320采样一个180字节完整包，约9KB/s含包头；独立加密通知特征F004与JSON控制通道分开。首版没有引入Opus库，也没有占用24KB Opus编码栈。Mac持续吞吐仍待实测。
- 32帧原始NOMI动作缩至144×156，RGB565共1,437,696字节放在闪存；不解码整屏、不申请宠物帧RAM缓存。LVGL池为32KB，主机相同控件布局占用约19.6KB。主机数据不代表设备空闲堆实测。
- 听写最长30秒，串行处理。Mac验证录音ID、包序号、帧数与尾包；音频不完整时不转写。开始单音100ms，完成为两段80ms上行双音（间隔30ms），均用合成纯音；DMA静音排空后重启RX，需实测首尾字和声学尾音。
- 输入前锁定应用、可编辑控件、原文及UTF-16光标/选区；采用一次标准粘贴并读回核验，保存剪贴板格式，临时内容只在本机，且不覆盖后来复制的新内容。焦点或草稿改变时保留文字；不确定输入结果时不自动重试，不按回车。不同应用对辅助功能支持不同，实机验收仍必要。
- 未插入的转写稿在电脑窗口内保留，可手动复制；只在进程内存中保留，不跨退出恢复。中断且未完整收到的音频不承诺恢复。本次未录制用户讲话、未更改输入权限。

依据：[Apple说明：SpeechAnalyzer转写不会发送语音至Apple服务器](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition)。
