# Codex 宠物形象自动同步

固件 `0.3.0-pets` 与电脑端 `0.8.1-pets.3` 继续使用唯一的“Codex 语音提醒”应用。
工牌昵称与形象独立，本次保留“那个谁”，并保留已有按钮、任务提醒和干净的听写提示音。

## 选择与图片来源

电脑端只读取 `config.toml` 中的 `desktop.selected-avatar-id`，以及
`.codex-global-state.json` 中必要的宠物条目。内置宠物从 Codex 安装包的 ASAR 图片
资源读取；本地宠物从 `pets/*/pet.json` 或旧版 `avatars/*/avatar.json` 读取；云端宠物
从桌面端图片缓存读取。全部为本机只读操作。这些是随版本变化的内部格式，缺失或
变化时保留工牌原形象，并显示等待重试。

云端形象索引会主动去掉下载地址的签名，因此适配器在 Chromium 图片缓存条目的
键前缀中匹配选中宠物的固定资源地址，只读取匹配图片的有限字节范围，并检查 PNG
分块 CRC 和尺寸。不读取 Cookies、登录凭据或其他缓存响应正文。已转换图片绑定
宠物标识、来源指纹、输出格式和完整 SHA-256；即使 Codex 的 HTTP 缓存被清理，
重启后仍可复用。若存在完整签名图片引用，也可使用无持久 Cookie/凭据的临时会话
下载，限制 HTTPS 来源、重定向和 20 MiB 大小。地址和签名不写入状态文件或持久元数据。

原生 ImageIO 在解码前检查完整图片尺寸：一版为 `1536 x 1872`，二版为
`1536 x 2288`。保留六帧待机、四帧运行、两帧就绪、两帧等待和两帧异常动画，
转换成 `144 x 156` RGB565，不改变角色形象。16 帧共占 718,848 字节。没有下载资源
通过校验时，工牌继续使用原有内置 32 帧形象。

## 传输与存储

程序起点仍为 `0x10000`，程序区调整为 `0x5f0000` 字节；在 `0x600000` 新增 2 MiB
的 `pet_assets` 数据区，分为两个 1 MiB 槽位。每槽先有 4 KiB 头部，再存动画数据。
验证头部 CRC、固定边界、代数与内容 SHA-256，最后写入提交字后新资源才有效。
中断传输或提交仍保留旧槽；开机验证损坏的新槽时可回退到旧槽。无需文件系统，
也不将整帧图片放入工牌 RAM。

`pet_begin` 协商传输和续传位置；加密 F005 特征接收带上传标识、偏移和图片片段的
有界数据包。电脑每窗口最多发四包，工牌确认提供流量控制，响应丢失后重新协商
位置。`pet_commit` 验证完整图片再启用。界面持有 LVGL 锁时切换映射资源，旧槽之后
才允许覆盖。更换宠物会替换尚未完成的传输，旧上传标识不能启用过期任务。

存储使用低优先级任务和有界队列；双方在听写、播报和紧急提醒期间暂缓传输，让
配对和声音优先。关闭工牌配件会取消待处理的图片获取任务。

## 分区迁移与验证

本次明确调整分区表，不属于相同分区更新。获批分段刷写前检查当前分区表，确认
NVS/PHY 范围与程序起点不变，且旧、新程序都不越过 `0x600000`。只写入已确认的
引导、分区表和程序，不整片擦除，也不将带填充的整包写过设置区。之后换宠物走蓝牙
更新图片，无需再刷固件。

自动检查覆盖 A/B 边界、续传、重复/冲突包、坏数据、中断提交、损坏回退和当前槽保护；
来源选择与图片缓存提取；原生图片尺寸、朝向、包格式、暂停续传、离线保护与重启复用。
实机吞吐、在 Codex 更换宠物以及与听写共存，另做硬件验收。
