# Codex 独立工牌设置

下方形象可行性章节保留早先 `0.2.3` 版本的记录；后续实现见
[宠物自动同步](codex-pet-sync.zh_CN.md)。

## 本次实现

固件 `0.2.3-accessory` 在现有状态帧中接收可选 `petName`，并在握手中报告
`petNameSupported: true`。默认昵称为用户指定的“那个谁”，使用现有中文字库显示。
昵称变更在录音和播放之外保存到 NVS，断开电脑或重启后继续保留。分区表与提示音
实现保持一致。旧电脑端没有发送昵称时，继续使用最后保存的昵称。

电脑端整合为唯一的“Codex 语音提醒”应用，分别配置工牌连接、工牌播报和电脑播报。
关闭工牌播报后仍能同步屏幕并使用按住听写。原来的虚拟音频设备设置自动迁移为
工牌播报开启、电脑播报关闭，保留用户原先的声音来源。新安装默认开启电脑播报、
关闭硬件配件。一个调度器管理接手、暂停、去重与两个声音来源；切换电脑输出设备
不会重播已经送达工牌的提醒。听写期间暂停两个来源的提醒播放。

## 宠物形象自动同步：可行性评估，尚未交付

目前工牌使用内置的 32 帧 NOMI 形象。在 Codex 更换宠物不会自动改变此形象。
工牌昵称与云端宠物名称独立；更改工牌昵称不会给云端宠物改名。设置页明确注明
形象暂不自动同步。

只读检查发现当前安装的 Codex 缓存中有稳定宠物标识、形象指纹与当前选择信息。
这些属于随版本变化的内部数据，并非公开的第三方订阅接口。
[官方 Pets 指南](https://learn.chatgpt.com/docs/pets) 也区分桌面本地自定义宠物与网页
宠物。后续适配器应只读取必要字段、容忍格式变化，并提供手动导入备用方式。
不得抓取凭据、保存会过期的资源下载链接，或导出全局应用状态。对话里的工具也
不能直接充当长期运行的后台同步客户端。

可靠方案需要版本化资源协议与明确的存储分区：检测选择变化、取得有权限的图片、
转换动画帧、分块传输、校验完整校验和，再原子切换。新资源验证成功前保留旧资源。
听写、播放和紧急提醒期间暂缓传输。因此不承诺蓝牙瞬间同步；初次加入资源协议后，
以后换宠物应能只更新资源，无需每次重刷程序。

当前 8 MB 分区没有资源区。后续可考虑在 `0x600000` 预留 2 MiB，将工厂应用区改为
`0x5f0000` 字节。两套 32 帧、`96 x 104`、RGB565 动画共占 1,277,952 字节（不含
资源头），可放入该空间；当前应用也能放入拟议应用区。这只是容量分析，改变分区
仍需单独评审迁移方案、获得刷写授权、测试损坏恢复、检查实际渲染并测量蓝牙吞吐。
本次没有加入资源分区或形象下载器。
